# ADR-0005：隔离工作区与最终原子应用

- 状态：已采纳
- 日期：2026-07-29

## 背景

Developer 可能经历多任务、重试和长时间 HITL。若每次工具调用直接修改 `CodeSmells/`，测试失败、用户拒绝、连接中断或半途异常都会留下部分修改；逐文件审批也无法让用户一次看到跨文件重构的完整语义。

## 决策

- 每个 run 创建 `baseline` 与 `working` 两份 `CodeSmells/` 快照。
- Developer 读写和 Reviewer 测试都指向 `working`。
- Reviewer 通过后生成全部文件的统一 diff，并固化 baseline/working 哈希。
- 只触发一次最终聚合 HITL。
- 批准恢复后重新验证快照哈希和真实源码 baseline，检测用户并发修改。
- 应用时在目标同目录准备临时文件，关闭句柄后用 `os.replace`。
- 旧文件先进入备份，失败时逆序补偿；删除和新增也进入同一变更集。
- 拒绝、失败和非成功终态清理工作区，保持真实源码不变。

## 原因

双快照把候选生成与源码提交拆成两个事务阶段。baseline 提供稳定 diff 和乐观并发控制，working 允许 Reviewer 测试完整候选。最终聚合审批让用户批准的是一个可复核变更集。

## 后果

正面：

- Agent 失败和用户拒绝不会污染源码；
- 跨文件 diff 在审批时完整可见；
- 可检测运行期间的用户修改；
- 进程内应用错误可补偿回滚；
- 所有任务共享一致候选树。

代价：

- 每个 run 复制 `CodeSmells/`，占用额外磁盘和时间；
- 这是应用级隔离，不是 OS 沙箱；
- 多文件 `os.replace` 加补偿不等价于掉电安全事务；
- 超大仓库需要增量快照或 VCS/worktree 方案；
- 强制终止进程可能留下待清理临时目录。

## 被否决方案

- Developer 直接写真实目录：失败和拒绝无法保证无副作用。
- 每次写入单独审批：审批疲劳，用户看不到跨文件整体。
- 仅在内存保存候选：无法复用正常文件工具和测试运行器。
- 依赖 Git reset 回滚：会覆盖用户未提交改动，不满足工作树保护要求。
